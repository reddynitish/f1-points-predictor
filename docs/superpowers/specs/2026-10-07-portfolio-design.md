# Portfolio improvements

Approved scope: the five recommendations accepted in chat on October 7, 2026.

Build a static, responsive dashboard from committed prediction and summary artifacts. A Python exporter embeds JSON in one HTML file; vanilla JavaScript provides event selection, probability bars, calibration and baseline comparison. No runtime downloads, model fitting, external fonts or paid infrastructure. Navy, ice blue and amber evoke a timing screen; a driver probability ledger is the main visual element. A static export is simpler to publish and verify than a server-backed app; Streamlit would introduce an unnecessary runtime dependency here.

Audit sprint endpoint semantics using immutable snapshots, recording all checked events and mismatches without altering frozen models. Adopt the already recommended interval cutoff, qualifying-row roster and sourced rank-missing overrides under the user's authorization to resolve the audit gaps. Preserve the limitations of final published classifications and historical revision timing.

Live scoring waits for complete archived-driver outcomes and validates prospective timestamps. Record run health, source freshness, collection failures, missed forecasts and partial results. Preserve archive immutability. No claim of successful prospective operation until actual future forecasts exist.

Analyze saved 2026 errors with whole-event uncertainty and segment counts. Development-only ablations use 2018–2024 and fixed diagnostic settings; they do not select or replace any frozen model. Do not rerun sealed evaluation or tune on spent periods.

Provide offline artifact verification, synthetic forecast demo and measured CPU runtime/memory. Verify source/config hashes and prediction-summary agreement. Document AI assistance without inventing personal ownership or learning claims. Focused commits follow passing checks; keep raw data and caches ignored.

Acceptance: clean checkout produces the dashboard and offline demo; meaningful tests reject malformed artifacts, premature scoring and stale/missing operational inputs; mobile and keyboard UI reviewed; make check passes; documentation matches saved metrics. Public hosting uses GitHub Pages only if available without billing changes.
